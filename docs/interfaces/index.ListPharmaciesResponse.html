    Interface ListPharmaciesResponse

    GET /v1/prescriptions/{id}/pharmacies response — the picker's list, framed by the prescription's state so a client can settle on it.

    When the prescription is no longer choosable (prescription.action !== 'choose') the list is EMPTY and the resource says why — render its action instead of an empty picker. In an e-prescribing deployment the list is also empty while address.step is set: run the address step first (PUT …/address answers with this same shape, list included). Otherwise pharmacies is ranked by distance from origin when one was used; without any origin (none passed, none cached) it is unranked and homeAddress invites you to geocode the patient's home and store it with POST …/home-location. Pre-select preferred when there is one, show licensure (when set) as a calm notice above the list, and print every distance in distanceUnit.

    licensure

    licensure: PrescriberLicensureNotice | null

    The prescriber-licensure notice to show above the list, or null when there is nothing to warn about. Set when the delivery address confirmed for this prescription is in another state than the one it was issued for — the patient's state at signing, or the state of the licence it was signed under — your tenant enforces state licensure, and the prescribing physician holds no usable licence there. So an address in the patient's own state can carry it too; read it on every list. NON-BLOCKING — the patient may still choose any pharmacy; render it as a calm notice, never an error (see PrescriberLicensureNotice). Null while the address step is pending, in a fax deployment, once the prescription is not choosable, when licensure is not enforced, and when the check could not run. Computed from the prescription on every read, so a reload shows it again. Added after the fields above.
