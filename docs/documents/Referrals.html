    Referrals — the signed requisition the patient carries

    A physician writing on an async consult can refer the patient without leaving the thread — to a specialist, for laboratory tests, or for an imaging exam. The platform renders a signed PDF requisition; the patient shows it, or hands it over, at the laboratory, the imaging centre or the specialist's office, and they take it from there. Nothing is transmitted: the patient carries the document.

    What a partner rendering its own chat has to do is show the document, because the platform's public /referral page asks for a birthdate, refuses consults that belong to a partner, and dies after 30 days. This guide is the whole loop: detect the link, resolve it, open the PDF.

    Everything below assumes the getting-started setup:

    export NATZAR_API="https://<your-assigned-api-host>"
    export NATZAR_KEY="pp_test_..."

    The embed widget (<natzar-async>, <natzar-agent>) does all of this itself — the route here exists for the headless integration.

    1. What lands on the transcript

    Two system notices, both ordinary async_consult.message events (there is no referral event type — your existing webhook handler already receives them), distinguished by their classification:

    Classification When What the body carries
    async:referral_issued The physician signed the referral. A one-line explanation of what to do with it, the referral link <host>/referral?id=<referralId>, and — as its own last paragraph — the validity sentence ("This link is active for the next 30 days.").
    async:referral_revoked The physician withdrew it. —

    Detect the link with REFERRAL_LINK_REGEX: group 1 is the referral id, the whole match is the URL to strip from the prose before you render the message — the same treatment as the consent, video, booking and pharmacy links. Then strip the validity sentence too: it is true of the anonymous web link and false of your surface, where the document has no window. The five sentences (one per platform language) are REFERRAL_LINK_VALIDITY_SENTENCES; remove whichever one is present, exact match:

    import {REFERRAL_LINK_REGEX, REFERRAL_LINK_VALIDITY_SENTENCES} from '@natzar/client/contract';

    const m = REFERRAL_LINK_REGEX.exec(message.body);
    if (m) {
      const referralId = m[1];
      let text = message.body.replace(m[0], '');
      for (const sentence of REFERRAL_LINK_VALIDITY_SENTENCES) text = text.replace(sentence, '');
      // render text.trim() + a file card with an "Open referral" button bound to referralId
    }

    (The runtime contract symbols live at @natzar/client/contract; the package root exports only their types. The root's detectLink and stripLink do the same detect-and-strip — sentence included — without the raw regex; see the SDK README.)

    2. Resolve the link

    curl -s "$NATZAR_API/v1/referrals/aB3xK9mQpZ4r" \
      -H "Authorization: Bearer $NATZAR_KEY"

    {
      "referral": {
        "id": "aB3xK9mQpZ4r",
        "externalPatientId": "pat-001",
        "consultId": "kQ7wN2pT9xLm",
        "kind": "laboratory",
        "status": "issued",
        "action": "view",
        "title": "Laboratory requisition",
        "physicianName": "Dr. Sarah Chen",
        "issuedAt": "2026-09-22T09:30:00.000Z",
        "revokedAt": null,
        "createdAt": "2026-09-22T09:30:00.000Z",
        "document": {
          "url": "https://…s3…/referrals/…/aB3xK9mQpZ4r.pdf?X-Amz-Expires=300&…",
          "downloadUrl": "https://…s3…/referrals/…/aB3xK9mQpZ4r.pdf?response-content-disposition=attachment…",
          "expiresAt": "2026-09-22T09:35:12.000Z",
          "fileName": "Laboratory-requisition-aB3xK9mQpZ4r.pdf",
          "contentType": "application/pdf"
        }
      }
    }

    Render from action ( ReferralLinkAction); it is decided server-side, so your screen, the app and the widget can never disagree:

    action Button Actionable
    view "Open referral" yes — open document.url (§3)
    revoked "Referral withdrawn" no
    expired "Link expired" no — never answered for a referral of yours; the fallback for a link you could not resolve

    Keep the button visible for the non-actionable values, with the label saying what happened. Show the title beside a document glyph (the file card the widget draws) and physicianName / issuedAt under it. There is no window on this API: the 30-day validity belongs to the anonymous web link alone, and a referral of yours reads action: 'view' for as long as it stands. 404 not_found means the id is not a referral of this tenant (or of a patient you provisioned).

    3. Open the document

    document.url is a presigned GET to the PDF served inline, minted on the read you just made and valid for minutes (expiresAt). Open it at once — a new tab, a PDF viewer, the OS viewer — and never store it: on the next tap, read the resource again for a fresh one. document.downloadUrl is the same object with an attachment disposition, for a "Download" control (a cross-origin download attribute is ignored by browsers; the response header is what makes them save).

    // Open the tab FIRST, inside the click, then point it at the URL — a
    // window.open that follows an await is a popup to every browser.
    const tab = window.open('', '_blank');
    if (tab) tab.opener = null;
    const {referral} = await fetch(`/my-backend/referrals/${id}`).then((r) => r.json());   // proxies GET /v1/referrals/{id}
    if (referral.document && tab) tab.location.href = referral.document.url;
    else tab?.close();

    Once the physician withdraws the referral, status is revoked, document is null and the transcript carries referral_revoked — flip the card to its disabled label. A referral is never edited: a mistake is a withdrawal plus a new referral, which arrives as a new notice.

    Issue a referral from a physician session

    An assigned clinician can write and sign the requisition without leaving the partner's provider portal. Use the browser-safe physician session, not the tenant key:

    import {connectPhysician} from '@natzar/client/physician';

    const desk = connectPhysician(session);
    const referral = await desk.inbox.issueReferral(consultId, {
      draft: {
        kind: 'imaging',
        modality: 'xray',
        examination: 'Right knee — 4 views',
        clinicalIndication: 'Persistent pain after injury',
        priority: 'routine',
      },
      lang: 'en',
    });

    For a lab and imaging request together, use desk.inbox.issueReferrals(consultId, {drafts: [labDraft, imagingDraft], lang: 'en'}). One notice/link is sent, but each draft produces its own signed PDF. The patient document reply and GET /v1/referrals/{id} include files for the complete bundle.

    The physician must be the consult's current assignee and have a complete prescriber profile. Specialist, laboratory, and imaging drafts are supported. Signing renders the immutable PDF, sends its referral card to the patient, and closes a referral_request as fulfilled; a normal conversation remains open. The operation is deliberately non-idempotent and the SDK does not retry it.

    Asking for one: referral requests

    When YOUR product decides a patient needs a requisition — a prevention module recommending a lipid panel, say — you do not need the patient to talk a physician into it. Open a referral request: an async consult of kind referral_request, which is a self-contained ask a physician answers with one referral instead of a dialogue.

    const {consult} = await natzar.asyncConsults.create({
      externalPatientId: 'u_1',
      consent: 'collected',                 // required for a request — there is nothing for a widget to consent to
      kind: 'referral_request',
      subject: 'Lipid panel (cholesterol)', // 1–120 chars; every notice the patient gets names it
      context: [                            // the ask the physician reads — be concrete
        'Male, 52. Last lipid panel more than 2 years ago; family history of early cardiovascular disease.',
        'Recommended by the prevention plan (CMQ/INESSS baseline). Requesting a fasting lipid panel requisition.',
      ].join('\n'),
    });

    What makes it a request rather than a consult:

    • It never silences the agent and never counts as the patient's one open thread: has_open_thread is not raised for it, and it may sit beside an open conversation and beside other requests. Nothing on your side has to check for one first.
    • It carries no messages: POST …/messages and POST …/replies on it answer 409 request_thread.
    • The physician's one move is to issue the referral. It lands on the transcript as the ordinary async:referral_issued notice (resolve and open it exactly as above) and the request closes with closedReason: 'fulfilled'. If they need to ask the patient something first they switch it to a conversation from their portal: kind becomes 'conversation', the patient is told a physician now reads what they write, and from then on it behaves like any consult you opened (has_open_thread included).
    • The transcript anchor is a partner:request_created system chip saying the request was sent — no link.

    kind is present on every AsyncConsultResource ('conversation' for consults that predate it); poll asyncConsults.get(id) for status / closedReason to show the request's progress, or watch the async_consult.closed webhook.

    What this surface deliberately does not do

    • No clinical content. ReferralResource is the link state, the document's title and the document itself: what was requested is printed on the PDF the patient carries, not modelled on the wire.
    • No listing, no patients/state fold. A referral is reached by the id in its transcript link — nothing awaits the patient, so there is nothing to surface on a cold screen.
    • No transmission, no tracking. The patient carries the document to the receiving service; whether the exam was booked or the results came back is between them.
    • Physician sessions cannot call the patient-side GET /v1/referrals/{id} route (403 forbidden); they can call POST /v1/async-consults/{id}/referrals to issue a signed document on a consult assigned to them.
    • Webhook payloads never carry document — they are stored durably, and a presigned URL is not. Read GET /v1/referrals/{id} when you need it.
